# Goals
In the DFS (Doka Filter Syntax), some characters are forbidden (#, %, ")
Implement the support of escaping in the doka parser. Those charaters should be prefixed with a # : ##, #%, #"

# Inputs
  - item search take a filter expression that must be something like 
    - category == "super #"extra#" player"
    - percent == "less than 10 #%"

# Ouputs
  - when a filter is incorrect, we should return a syntax error like today
  - when the filter is correct, its string literal should be converted into a valid string in the intermediate state :  
    - "super #"extra#" player" gives : super "extra" player
    - "less than 10 #%"  gives : less than 10 %

  
# Preconditions
- none

# Postconditions
- Not a simple forbidden char appears alone in the original string literal.

# Business rules
- In a string literal, #, % and " **must** be prefixed by a # to be considered as valid.
- A `#` inside a string literal **must** be the start of one of the escape sequences `##`, `#%` or `#"`. A `#` followed by any other character (including the end of the literal) is a syntax error.
  - example : `"see paragraph #6"` is rejected — the `#` is followed by `6`. Correct form : `"see paragraph ##6"`.
  - example : `"hello #"` is rejected — the `#"` is consumed as an escaped quote, leaving the string unterminated (this surfaces as the existing `UnclosedQuote` error, not as `InvalidEscapeSequence`).
- Any isolated forbidden char (a bare `"`, `%` or `#` not part of an escape sequence) is a syntax error.

# Errors

A new variant is added to `FilterErrorCode` in
[`document-server/src/filter/filter_lexer.rs`](../../document-server/src/filter/filter_lexer.rs),
following the existing PascalCase naming and message style (a short English
sentence ending with `at position {char_position}`, no `{}` placeholder for the offending character).

- `InvalidEscapeSequence`
  - fires when a `#` inside a string literal is not followed by `#`, `%` or `"`,
    **or** when a forbidden character (`"`, `%`, `#`) appears in a string
    literal without being part of a `#`-escape sequence.
  - message: `Invalid escape sequence in string literal at position {char_position}`

The trailing-`#` case (e.g. `"hello #"`) is **not** reported as
`InvalidEscapeSequence` — the `#"` is consumed as an escaped quote, so the
existing `UnclosedQuote` variant fires instead.
